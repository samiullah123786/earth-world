# AgentsEarth world and creation architecture review

12 October 2026. Read-only review; proposed direction, not implemented infrastructure.

## Decision

Retain the existing Kernel and Three.js client. Make an elevated angled observation view the primary experience, a citizen-follow view the secondary experience, and first-person exploration optional. Reuse the current semantic map and ownership system. Introduce an engine-independent creation document and action/observation contract before expanding graphics or physics. Do not migrate back to 2D to solve agent autonomy: renderer dimension does not supply that capability.

The scene has coherent cream homes, timber, vegetation, roads and persistent citizens. The workshop is a convincing local planning surface. The live scene still obscures actors with tall buildings, panel chrome and overlapping labels. Its world art is product-specific; its observer interface does not yet make that product's activity easy to understand.

## Proposed shared architecture

External agent or owner input -> validated semantic action -> Kernel authorization/ownership -> authoritative simulation and committed state -> sequenced projections -> human map/dashboard and agent observations.

The two audiences share facts, IDs, revisions, positions and affordances. Humans get the rendered view and inspection controls. Agents get structured objects, reachable routes, material inventories and available actions. A screenshot observation is an optional additional tool when visual reasoning is needed; it should carry the same revision/time as its structured snapshot. Do not require image-model calls for routine pathfinding or building.

Use chunk-local coordinates and interest filtering. Every placed object has a stable ID, owner, creation version, material/shape definition, collider, behavior state and event history. Simulation physics owns transient transforms under an explicit authority boundary; Kernel retains permissions, ownership, currency and durable committed outcomes. Avoid two competing writers. Store checkpoints and revisions rather than every display frame.

## Proposed body and animation contract

Persistent avatar components: body proportions within a bounded compatible rig, face, eyes, hair, clothing, shoes and cosmetic accessories. Verified role/capability/tier data remains server-owned and visually distinct from cosmetic choice. Face appearance does not reroll on reconnect. Expand composable choices beyond 144 complete textures; do not claim mathematical uniqueness from a finite palette.

Action controller: idle, walk, run, turn/look-at, wave, talk, sit, carry, pick-up, place, hammer/build, water and rest. Each semantic action carries target, start/end time, completion state and interruption rules. Head yaw/pitch follows valid targets within joint limits; arms/legs use shared clips; hand/foot correction is optional at close range. Overview uses inexpensive instanced motion and activity indicators; follow view uses richer animation. Ragdolls are not needed for social gestures. Not every clip in the existing 27-clip asset belongs in the positive-world product (death/combat clips should not be exposed merely because the asset includes them).

## Proposed creation language, logic and physics

An agent creates a versioned declarative assembly from foundations, posts, beams, floors, walls, openings, stairs, roofs, paths and furnishings. Shapes use approved parametric bounds/materials; agents compose them rather than send arbitrary mesh URLs or executable scene files. Validate plot containment, support, weight/load budgets, traversable doors, roofs/overhang clearance, neighbors and resource cost. Compile the same document into preview, appearance, collision, navigation and agent affordances. Preview reports actionable errors; commit is atomic, version-checked and recoverable. Build jobs visibly apply stages and resume without duplicate parts or charges.

Behavior components can describe switches, doors, sensors, timers, counters, storage, crafting stations, shops and game goals. A bounded event-condition-action graph supplies logic. Cap work per tick, reject invalid references/cycles or require explicit bounded delays, and prevent behavior from spending tokens or modifying another owner's property without the same Kernel authorization. Mechanical components add hinges, sliders, joints and motors with bounded force/speed. Physics supplies motion; gameplay components supply meaning. Neither one alone creates an autonomous functional world.

Static constructions should not keep simulating needlessly. Activate physical simulation around agents and active interactions; leave stable buildings static. Begin with dynamic props and doors before vehicles, multi-floor navigation or unrestricted machinery. Rapier supports rigid bodies/joints/controller queries, but engineering-grade fracture/load analysis is separate and should not be advertised as implemented or supplied automatically.

External builder loop: observe -> plan -> validate/preview -> reserve -> move/build -> inspect actual committed result -> revise. User owners set standing consent, land/resource budgets and runtime budget. A live worker is required for continued thinking; disconnected citizens retain their identity/home and may follow explicitly supported approved plans, never pretend a brain is thinking. Agent-generated code/plugins require a separate isolated execution/design decision and are outside the proposed first creation language.

## Framework decision matrix (official documentation checked)

| Option | Supplied capability | Decision for this project |
|---|---|---|
| Three.js + Rapier | Existing 3D rendering/animation plus separate rigid bodies, colliders/joints | Recommended incremental path; new simulation/creation integration still required |

| Phaser + Matter | 2D sprites/tile maps and rigid-body 2D physics | Good only for a deliberate new sprite-world direction; does not solve missing creation semantics |
